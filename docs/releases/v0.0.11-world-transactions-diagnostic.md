# v0.0.11 world transaction diagnostic

This prerelease reduces ice/enemy preparation while preserving the original
source clock and mapped graphics. **The gain is modest; visible stepping remains.**
Active drawing rises from9.80to10.34pictures/s on NTSC (+5.49%) and from9.70to
10.28on PAL (+6.02%) in the same input-only route. This is not original-speed
presentation or a smooth30/60fps release.

## Implementation and measured result

Ice NAME programs are compiled into final, generation-specific templates in
verified empty ROM tails. Enemy rows use a register-held cursor and an immutable
occupancy byte instead of a generic geometry lookup for each normal primitive.
Shared ice/enemy cells retain the original full-geometry fusion path. All colors,
actors, four ice/enemy lanes, multicolor player and left black mask are preserved.
There is no source-logic, collision, audio-order or movement-rate change.

The disjoint NTSC foreground profile measures world preparation at88305cycles,
down12.19% from100566. Complete foreground preparation falls6.48%, from201312to
188260cycles per active snapshot. These are separate active-snapshot populations
on the same2252-step route, not a same-frame microbenchmark. Whole-route picture
rates19.53NTSC/17.29PAL include lighter attract/death phases; the slower active
rates above are the relevant gameplay numbers. Source logic remains about59.92
original steps/s on both TV families.

## Setup, exact artifact and controls

Use an MSX1 at standard speed,64KiB RAM/16KiB VRAM, TMS9918-family VDP and built-in
PSG. The4MiB cartridge uses **ASCII16** mapping. No expansion or MSX-DOS is needed.
In openMSX choose an MSX1 machine such as C-BIOS_MSX1 and normal100% speed. Compare
with0.0.10under the same machine/video/speed settings; comparing with its older
render-coupled predecessors confounds simulation and drawing speed.

Source commit: `a43e2f1b265ef956ee154e82a198a17f9831a220`.
ROM SHA-256: `fbf81a5eafa536f95497be22c787812046cf59a38eb962ee28230b3fc8f9ec99`.
The attached `build.json`, `validation.json` and `SHA256SUMS` bind the exact ROM.

F1 resets/starts. Arrows or joystick move/jump; a fresh Space/joystick-fire press
reverses a contacted blue ice row. F2 selects original variations: zero/one/two/
three short presses choose regular one-player / regular alternating / advanced
one-player / advanced alternating, followed by F1. Keep default F3/F4 diagnostics.

## Checks and limits

The release validation records548host tests,2115source scenes and1920density
scenes,4507native CPU/all128RAM checkpoints, and1379coherent NTSC/PAL pictures.
Pixel, physical-owner, active-page, RAM-code, stack and source guards pass. Both
TV families have zero late VBlanks; PAL also exercises expanded-slot built-in RAM.
Nine directed hardware-IRQ boundaries per TV family preserve main/alternate/index
registers, stack and bank. An AF2 corruption negative control verifies the oracle.
Independent review checked all2560legal NAME contexts,8448occupancy entries and
complete patch replay. Its geometry-error stack defect was reproduced with forced
carry and corrected, then the failure-return test passed on the final ROM.

These automated/emulator results do not establish human playability, manual audio,
all-level/controller or physical-hardware acceptance. Sparse coherent snapshots
still omit intermediate source states. The maximum gap and its distribution are
recorded in the performance workbook; an average gain is not a claim that judder
has been eliminated. Earlier ROMs and evidence remain preserved.

## Tests requested from the human

1. Cold-start0.0.11, wait10seconds, tap F1. Compare with0.0.10at the same100%
speed. Walk right/left and jump repeatedly through all four lanes. Report whether
visual stepping and delayed visible response improve, stay similar or worsen.
2. Watch the left entry/wrap boundary, fish/enemy copies, ice colors after landing,
and moments where an enemy shares a tile row with ice. Expect the same graphics
and colors, with no trails, missing pieces, stationary fragments or flicker.
3. Land, release/repress fire to reverse a blue row, collect fish and lose a life.
Check collision/jump timing, temperature countdown and the corresponding sounds.
Compare real-time mechanics with the Atari original separately from visual steps.
4. If available, repeat on PAL and real MSX1 hardware. Report machine/BIOS/VDP,
loader/mapper, emulator version/speed, variation, exact actions and release number.
A short video with audio is useful, especially where horizontal movement stutters.
