# v0.0.2-renderer — synthetic MSX1 renderer benchmark

## Current state

This is a **diagnostic benchmark, not a playable Frostbite port**. Synthetic
ice/creature shapes, a three-color player, bear, igloo and text exercise a hybrid
SCREEN2 renderer. Shapes, row positions and colors are provisional. White/blue ice,
threat poses and igloo stages change every frame deliberately to stress transfers;
this is not final game animation. The diagnostic itself is silent.

- ROM: `frostbite-0.0.2-renderer.rom`, **32,768 bytes**, Normal/plain32KiB cartridge.
- Source: `b249373be1cc2382f87b5bb97caa865ae0c6641c`.
- SHA-256: `111ded95de3c91ff92093abe5fcee4b436150a99ee96a5a9634dfc9ebeffd4c7`.
- Target: normal-speed MSX1, 64KiB RAM, 16KiB TMS9918-family VRAM. No mapper,
  RAM expansion, turbo, disk or extra sound hardware is required.

Checks passed: 129 host tests; 643 independent pixel/SAT scenes; ten streams of
240 consecutive frames covering every layout/width and actual SPACE transitions
on NTSC and PAL; at most four sprites per line; minimum 29-cycle VRAM spacing; source/input,
RAM/stack guards; emulated Left/Right and SPACE edge/hold/re-press; five deliberate
failure controls. PAL preserved 286 synthetic source reservations in 240 frames.
The suite includes a measured 10,018-cycle surrogate per required step. It does
not establish the future native core/audio/input cost. The worst crossing stress
paced case leaves only 747 NTSC cycles of its budget (58,989 / 59,736).
Crossing PAL peaks at 68,995 / 71,364 cycles; commits stay in VBlank.
Independent review found and reproduced an overrun in the earlier unpublished
candidate; bulk crossing uploads and mandatory all-mode/SPACE-transition gates
corrected it before release. The release tag includes later evidence/docs; the
exact tested ROM and capture producer remain the full source commit above.

`preview-vram.png` is a reconstruction of actual emulated VRAM, with approximate
RGB colors. It is not a framebuffer screenshot. Live graphical capture on the
agent host timed out; manual GUI, expanded cartridge slots, listening and real
hardware remain human checks. The complete numeric evidence is attached as
`renderer-result.json`. The older v0.0.1-diagnostic release remains unchanged.

## Human tests

1. Verify `SHA256SUMS`, then load the ROM as **Normal32KiB**. Use an MSX1 with
   64KiB RAM/16KiB VRAM, normal CPU speed and normal sprite limits; disable turbo
   and expansions in the emulator. In openMSX use C-BIOS_MSX1; test a PAL MSX1
   profile as well if available. On hardware use a plain32KiB cartridge mapping.
2. Allow up to five seconds for startup. Expect the `FROSTBITE RENDER BENCH` title,
   `SYNTHETIC NO GAMEPLAY`, a gray shore and four rows of moving test objects/ice.
   The player and bear deliberately overlap initially. Auto-changing colors and
   igloo stages are intentional; expect continuous motion rather than freezes.
3. Hold **Right** briefly, then **Left**. Expect the player to separate from the
   bear and the top-right hexadecimal X value to increase/decrease. Hold Right
   for three seconds to reach `9F`: the player becomes clipped at the viewport
   edge. Move Left again; the full shape should return. Only keyboard Left/Right
   movement is implemented in this diagnostic.
4. Tap **SPACE** once: ice width and the stress row layout change. Hold SPACE for
   one second: they must not toggle repeatedly. Release, wait briefly and press
   again: the previous width/layout returns. This is a diagnostic selector, not
   the original game's reversal action.
5. Let it run for 20 seconds on NTSC and PAL. Report missing graphics, unexpected
   disappearing sprites, persistent corruption, freezes or failed controls.
   No gameplay, scoring, collision reaction or PSG sound is expected yet.

Send machine/emulator version, VDP/TV standard, RAM/VRAM, CPU speed, cartridge
slot/mapper and ROM hash, plus the exact action that failed and a screenshot or
short video. A successful physical test is especially useful. A clear human
verdict is needed before any manual or physical acceptance is recorded.
