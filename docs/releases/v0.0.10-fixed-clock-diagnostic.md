# v0.0.10 fixed-clock diagnostic

This prerelease tests original-time game logic independently of drawing.
**It is not a smooth-play release: active drawing is about9.8fps NTSC/9.7fps PAL
in the measured route.** The simulation runs about59.92original steps/s on both
TV families, retaining the original source code/order, contacts, input and PSG
events. Every displayed snapshot retains the graphics, colors, actors, player
and left black mask. This is not60fps graphics or a final performance solution.

## Load and controls

Use standard-speed MSX1,64KiB RAM/16KiB VRAM, TMS9918-family VDP and built-in
PSG. The attached4MiB `.rom` requires **ASCII16 cartridge mapping**, not a RAM
expansion or MSX-DOS. In openMSX select an MSX1/C-BIOS_MSX1 machine, normal100%
speed, and ASCII16 when the loader asks. The release tag and attached `build.json`
identify the exact source commit; `SHA256SUMS` identifies all attached bytes.

F1 resets/starts the original game. Arrows or joystick move/jump. A fresh Space
or joystick-fire press reverses a contacted blue row. F2 is original Game Select:
zero/one/two/three short presses choose regular one-player / regular alternating /
advanced one-player / advanced alternating; press F1 to start. Keep the default
F3/F4 diagnostic view for the requested tests.

## Automated checks and limitations

The public source chain reconstructs the exact Q-E baseline and the diagnostic.
The source/density gates cover2115/1920scenes with zero different frames. Native
NTSC/PAL input replays compare4507CPU/all128RAM checkpoints and1355complete
committed pictures, including active-page and physical-owner protection. Both
have zero late VBlanks; maximum IRQ service is29810NTSC/53268PALcycles. Observed
stack use is64/62bytes of128. PAL also checks built-in RAM in an expanded slot.
Directed hardware-IRQ alignment exercises nine mapper/VDP/stream/snapshot
boundaries per TV family, with an AF2 corruption negative control. Host tests and
original-free CI are separate from these emulator checks; exact delivery results
are in `validation.json`.

The renderer still shows old coherent snapshots while preparing the next image.
Expect visible steps and delayed visual feedback. Whole-route picture rates
19.23NTSC/16.94PAL include lighter phases; active action is slower, as stated
above. No manual listening, alternating-controller, all-level or physical-hardware
acceptance is implied. Prior releases and local M/N/O/P/Q controls are preserved.

## Tests requested from the human

1. Cold-start the attached ROM. Wait10seconds, tap F1, and play at normal speed.
   Check that the original graphics/colors and all four ice/enemy lanes remain
   intact. Report persistent corruption, missing actors, freezes or a boot failure.
2. Compare with the Atari original at normal speed. Walk horizontally, jump
   repeatedly between rows, and let the temperature count down. Assess the
   **real-time movement/jump/timer speed separately from visible judder**. This
   test asks whether the restored game clock feels correct despite sparse images.
3. Land on ice, release/repress fire to reverse a blue row, and collect fish or
   lose a life when reachable. Check action/collision timing and listen for the
   corresponding effects. Report a stuck tone, missing effect or reset problem.
4. Tap F1 during an effect, then try F2 variations. If two controllers are
   available, check alternating turns use their correct ports. These paths need
   human feedback; the primary clock replay is one-player.

Return the release/version, machine/BIOS/VDP, NTSC/PAL, emulator/version or physical
loader, selected variation and exact actions. A short video with audio and an
Atari comparison is useful. Please distinguish incorrect game speed, visual
stepping, delayed visible response and a collision/mechanics mismatch.
