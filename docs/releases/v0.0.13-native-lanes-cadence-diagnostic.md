# v0.0.13 — Native lanes and cadence diagnostic

This addresses the reported slideshow movement with a substantial renderer
change. Native ice lanes, bounded enemy sprites, precompiled player shapes and
selective background/header updates replace repeated general composition. Enemy
lanes fall back to exact tiles whenever sprite capacity or clipping requires it.
The black left mask and the corrected player palette remain intact.

The original logic, jump trajectory, collision, input and PSG clock are unchanged.
Player and world still come from the same coherent source snapshot.

## Measured improvement, remaining limitation

Same original input route, standard-speed MSX1:

| Active gameplay metric | v0.0.12 | v0.0.13 |
| --- | ---: | ---: |
| NTSC complete pictures/s | 10.613 | 18.221 |
| PAL complete pictures/s | 10.544 | 17.216 |
| NTSC mean picture gap | 94.22 ms | 54.88 ms |
| NTSC P95 picture gap | 133.47 ms | 83.44 ms |
| NTSC longest picture gap | 150.19 ms | 116.82 ms |
| Whole foreground preparation | 182,896 cycles | 95,808 cycles |
| Original jump update states shown | 132/390 | 229/390 |

Across26 complete jumps, the original has15 vertical updates per arc. The average
number actually presented rises from5.08 to8.81. The underlying trajectory and
its duration are unchanged. Active presentation improves71.7% NTSC/63.3% PAL;
whole foreground cost falls47.6%. Snapshot populations differ because cadence
changes; this is a complete-route comparison, not a matched-frame microbenchmark.

**This is still a diagnostic, not a claim that the slideshow problem is solved.**
Rendering remains below30fps, some jump positions are still never shown, and
occasional gaps still exceed100ms. Source/input logic remains approximately
59.92steps/s. Responsive controls and pixel equivalence do not prove smooth motion.

## Tests requested from the human

1. Load on a **standard-speed MSX1** with64KiB RAM/16KiB VRAM and built-in PSG.
   Select **ASCII16**, emulator speed100%, and the same machine/video settings
   used for v0.0.12. Tap **F1** to start. Identify NTSC or PAL in your feedback.
2. Walk left/right on shore, then repeatedly jump down/up and steer horizontally
   while airborne using arrows or joystick. Compare directly with v0.0.12.
   Expect noticeably more intermediate images and the same jump duration/control
   response. Report where movement still looks stepped; smooth30fps is not expected.
3. Ride the four ice lanes; release/repress **Space/joystick fire** to reverse a
   blue lane. Collect fish and pass enemies, including the left/right edges.
   Expect unchanged contact/collision and no flicker, missing actors, trails or
   new color changes when an enemy shares the player's scanlines.
4. Watch score, temperature, lives and igloo while landing, building and losing
   a life. Note whether these events coincide with a visible pause. Digits and
   igloo blocks must not freeze or disappear; normal player colors must return
   after death, and audio behavior should remain the same.
5. Please report release, machine/emulator, TV mode and speed. A short recording
   with audio covering horizontal movement, several jumps and one death is most
   useful. Keep physical-hardware observations identified separately.
